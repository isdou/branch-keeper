# Contributing

Thanks for helping improve Branch Keeper.

## Before you start

- Open or join an issue for changes that affect behavior, data shape, or workflow semantics.
- Keep pull requests focused on one problem or improvement.
- Preserve Branch Keeper's core principle: deferred product directions should remain explicit, inspectable, and user-confirmed.

## Development

1. Create a branch from `main`.
2. Make the smallest change that solves the problem.
3. Update documentation when behavior or setup changes.
4. Run the relevant tests or manual checks before opening a pull request.

## Pull requests

Please include:

- What changed.
- Why the change is needed.
- How it was verified.
- Any follow-up work that is intentionally out of scope.

Prefer clear commit messages and avoid unrelated formatting-only changes in the same pull request.
